# DOC-005 — GCP post-change smoke (2026-08-12)

Mục tiêu: xác nhận route và workload dài hạn vẫn sẵn sàng sau lần rà soát mã/tài
liệu. Đây là kiểm tra chỉ-đọc qua IAP; không chạy ingest, không gửi câu hỏi tới
model và không thay đổi dữ liệu.

## Lệnh đã chạy

```bash
gcloud compute ssh kuberag@kuberag-server \
  --project=kube-rag-platform \
  --zone=asia-southeast1-b \
  --tunnel-through-iap \
  --command='sudo k3s kubectl get nodes --no-headers; \
    sudo k3s kubectl -n rag get deployment kuberag-rag-api kuberag-web --no-headers; \
    sudo k3s kubectl -n prefect get deployment prefect-server prefect-worker --no-headers; \
    for P in / /api/v1/status /hostname; do \
      printf "%s " "$P"; \
      curl --silent --output /dev/null --write-out "%{http_code}\\n" \
        "http://10.42.0.2:8080$P"; \
    done'
```

```text

prefect-server    1/1   1   1
prefect-worker    1/1   1   1

/               200

/hostname       200
```

Kết luận: control plane, hai worker, frontend, API status, Prefect server và
Prefect worker đều sẵn sàng tại thời điểm kiểm tra. Đây không thay thế RAG
end-to-end query hoặc rehearsal; các hoạt động đó được tách riêng để không
tiêu tốn CPU inference hoặc quota rate-limit.
